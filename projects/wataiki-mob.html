Overview

Wataiki Mob is a document-services platform. Users subscribe — yearly or monthly — to access services such as ID cards, photo shoots, merged PDFs, OCR extraction, documents, and QR codes. The admin portal is where the business runs: user management, roles and permissions, subscription review, and the document pipeline.

Subscriptions are not just rows in a table. Each one is attached to a customer, an uploaded document image, a plan, a start and end date, a price in Algerian dinars, a review status, and a locked or unlocked state. At the time of capture the portal held 56 subscriptions — 49 pending, 6 approved, 1 rejected — with 49,600.00 DZD in total earnings, 54 yearly plans and 2 monthly plans.

  • Subscription KPIs: total, pending, approved, rejected, locked, and unlocked.
  • Yearly and monthly plans with pricing, dates, and earnings in DZD.
  • A searchable subscription list with document thumbnails and row actions.
  • A detail view with customer contact information, attached document, and review status.
  • Document services: ID cards, shoots, merged PDFs, OCRs, documents, and QR codes.
  • User management plus roles and permissions for the admin team.

My role

I built the admin portal end to end — the data model, the subscription workflow, the document services, and the dashboards the team uses to review and approve requests.

  • Modelled users, roles and permissions, plans, subscriptions, documents, and review history.
  • Built the dashboard aggregations: subscription counts by status, locked/unlocked totals, plan mix, and earnings.
  • Built the subscription list with search, document thumbnails, date ranges, status, lock state, and per-row actions.
  • Built the subscription detail page with customer details, attached document, price, review status, and edit flow.
  • Implemented the document pipeline: ID cards, shoots, merged PDFs, OCR extraction, documents, and QR code generation.
  • Added role-based access control so the admin team only sees the sections it needs.

Key features

Subscription dashboard

One screen for total, pending, approved, and rejected subscriptions, plus locked and unlocked counts and earnings.

Review workflow

Every subscription starts pending, is reviewed by an admin, and can be approved or rejected — then locked once it is active.

Customer records

Name, email, phone, and the uploaded document sit together on the subscription, so support has the full picture.

Plans & pricing

Yearly and monthly subscriptions with explicit start and end dates, prices in DZD, and total and yearly earnings.

Document services

ID cards, shoots, merged PDFs, OCR extraction, documents, and QR codes — each with its own admin section.

Roles & permissions

User management and granular permissions keep the admin team separated by responsibility.

Tech stack

An internal portal with money and documents in it, so the important parts are the data model, the audit trail, and the safety of every bulk action.

  • Laravel
  • PHP
  • MySQL
  • REST API
  • OCR extraction
  • PDF merging
  • QR code generation
  • Role-based access control
  • Git

Architecture: a Laravel admin application over a MySQL schema built around users, roles, plans, subscriptions, and documents, with a document layer that merges PDFs, extracts text through OCR, produces ID cards, and generates QR codes — all tied back to the subscription that unlocked the service.

Outcome

Wataiki Mob runs its subscriptions from a single admin portal: 56 subscriptions tracked, 49,600.00 DZD in recorded earnings, and a review flow that keeps pending requests from getting lost between messages. Approving, rejecting, locking, and unlocking are explicit actions with a visible state.

Because the document services and the subscription live in the same system, an approved request immediately has everything it needs — the customer, the uploaded document, the plan dates, and the price that was paid.
